# frontend — 웹 시연 화면

`index.html` 한 장 (외부 라이브러리 없음). 서버: `scripts/web_demo.py` (Python 내장 웹서버).

```bash
.venv/bin/python scripts/web_demo.py      # http://127.0.0.1:8790
```

PM·팀장이 5초 안에 "무엇이 막혔고, AI가 왜 그렇게 봤고, 내가 무엇을 결정해야 하는지"를 알 수 있게 구성했다.

- 상단: 프로젝트·AI 모니터링 상태·가상 시각·답장 해석 모델, 시나리오 선택, [새로 시작] [다음 단계] [자동 진행], 시연 모드
- 요약 카드: 전체 업무 / 정상 / 확인 필요 / 막힘 / 해결 (실제 Agent 판단 개수)
- 지금 확인이 필요한 업무: 7단계 진행 표시(이상 징후 발견 → 담당자 확인 → Block 확인 → 지원자 탐색 → PM 승인 → 지원 요청 → 해결 확인),
  AI 판단과 근거, 담당자와의 대화·AI 해석, 지원 제안(근거 기록), PM 결정, 해결 확인
- AI 판단 보정: Memory가 판단 기준을 어떻게 보정했는지 (개인 평가·점수에는 사용하지 않음)
- AI 활동 기록, 팀 업무 현황 표, Agent 활동 상세(개발·검증용 지표와 원본 기록)

원칙
- 승인 전에는 지원 요청이 전송된 것처럼 보이지 않는다. 해결 확인은 실제 작업 기록이 생긴 뒤에만 나온다.
- 같은 시각에 일어난 사건은 한 단계씩 순서대로 보여 줄 뿐, 아직 일어나지 않은 사건은 보여 주지 않는다.
- 기술 ID(T08, ACT-, RPL-, REV-, MEM-)는 기본적으로 숨기고 "근거 상세 보기"와 "기술 ID·원본 기록 함께 보기"에서만 보인다.
- 시연 모드: 근거 상세·원본 기록을 숨기고 핵심 사건만 보여 주며, 승인 버튼을 크게 표시한다. 자동 진행은 PM 결정에서 멈춘다.

화면용 정보는 `contrilog/webui/view.py`(읽기 전용 ViewModel adapter)가 Agent가 남긴 기록에서 읽어 `/api/state` 응답의 `view`에 담는다.
Agent·Tool·Memory는 호출·수정하지 않는다.

원격 서버에서 실행하면 VS Code의 포트 전달(8790)로 로컬 브라우저에서 연다.
